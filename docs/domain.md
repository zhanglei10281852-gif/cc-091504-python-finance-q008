# 领域说明

股票挂钩票据由标的篮子、观察日、障碍水平、票息与到期交付规则构成。停牌、节假日顺延、公司行动和行情更正会改变观察证据。现金流一旦支付便成为独立账务事实，后续修订通常通过差额调整反映，而不是删除原记录。

`reference/domain.json` 保存可公开的示例枚举与精度约定。正式业务记录应使用稳定标识，并区分业务发生时间、系统接收时间和记录版本。

## 引擎模型（src/engine/）

### 版本化与时间点固定

- **条款**：每次发布产生递增版本，`effective_from` 为业务生效日。篮子成分变更即一个 `reason=basket_change` 的新版本。每个观察固定使用该观察日适用的条款版本，重算历史观察点不会漂移到新条款。
- **行情**：同一（标的、日期、类型）重复登记产生递增版本，最新版本为准。状态：`provisional`（临时）、`official`（权威）、`suspended`（停牌）、`cancelled`（撤销）。发行人更正 = `reissue`（补发新版本）或 `cancel`（撤销）。
- **观察**：同一（产品、计划观察日、类型）的逻辑观察以版本链演进，每版固定条款版本、实际观察日、逐标的证据（价格记录 ID、版本、调整因子、表现）与障碍判定。

### 观察状态机

- `confirmed`：全部标的取得权威收盘价，障碍判定生效。
- `pending_confirmation`：存在临时价格（只能待确认），或逐日敲入观察缺价待补。
- `postponed`：自动赎回/期末观察缺价，按条款 `missing_price_rule` 顺延至下一营业日，记录 `next_attempt`，绝不静默跳过。
- `unresolved`：顺延超过 `max_days` 仍未取得权威价格，待人工或补数。

节假日顺延（`modified_following` 等）与停牌顺延都在观察记录中留下 `rolled_from` / `roll_reason` / `next_attempt` 计算路径。公司行动以调整因子作用于除权日后的期初价，证据中保留 `factor` 与 `initial_adj`。

### 现金流状态机与更正原则

`projected → confirmed → paid → adjusted`（另有 `cancelled` 终止态）。

- 已确认观察驱动现金流**确定性再生成**：票息（含记忆补付）、自动赎回、到期现金/实物交付。
- 补发/撤销行情触发观察新版本，**尚未支付**的现金流以新版本重算（可升可降，confirmed ↔ projected ↔ cancelled）。
- **已经付款**的项目绝不抹去：原金额与结算记录保留，状态转为 `adjusted`，差额以 `adjustment` 现金流（可为负，方向 `collect`）体现；调整单自身同样走 confirmed → paid。
- 结算按 `idempotency_key` 幂等：同一指令重试返回原结算单，不重复付款；同键不同现金流返回 409 冲突。

### 查询

- 运营视图（`GET /products/{id}`）：各标的逐日证据、障碍判定与距离、下一观察日、预计现金流、合同现金流样例对照。
- 争议复原（`GET /cashflows/{id}/explanation`）：付款成立时的条款版本、观察版本、行情版本与逐步计算过程，以及后续更正产生的新观察版本与差额调整链。

`reference/seed/` 保存争议批次样例：ACN-2026-001（停牌后补价 → 敲出 → 发行人更正撤销敲出 → 已付赎回差额追回）与 ACN-2026-002（篮子变更、逐日敲入、到期现金损失交付）。
